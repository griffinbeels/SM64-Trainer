# Default strategy per segment definition — "Standard" for castle movements

Date: 2026-07-24
Status: approved (design), ready for planning

## Problem

There is basically one way to do a castle movement. Yet all 55 seeded
movement segments ship with no strategy at all, so:

* every movement card renders the picker in its red `needs-strat` state,
  which is supposed to mean "you forgot", not "there is nothing to pick";
* attempts close with `strat_tag=None`, and `views._current_pbs_by_strat`
  skips untagged PBs — so a movement can never be ranked, no matter how many
  times it is run;
* the only way out is picking a strategy by hand on 55 cards.

The user's framing: movements should default to **"Standard"**, and for a
movement "no strategy" is not a legitimate choice at all.

"Standard" is already the corpus-wide convention — it is the most common
strategy name in `data/rank_standards.seed.json` (48 of 102 entities).

## Scope

* **In:** the 55 castle-movement segments generated by
  `tools/build_defaults_seed.py::_movement_row`.
* **Out:** the 10 legacy trick segments (LBLJ, MIPS Clip, Lakitu Skip, the
  three pipe entries, BitS Entry, Bowser 1–3). Several of those carry real
  competing strategies in the rank standards; a forced default would be a
  lie. They keep `default_strat = NULL` and behave exactly as today.
* **Out:** user-created segments (no seed row, so no default).
* **Out:** any UI for *editing* a default. The corpus is the only author.

## Design

### 1. `default_strat` is part of a segment definition

A segment definition gains one nullable field, carried end to end:

| Layer | Change |
|---|---|
| db | migration **v13**: `ALTER TABLE segment_defs ADD COLUMN default_strat TEXT;` — plus the column in `insert_segment_def`, `update_segment_def`'s `cols` map, and the `segment_defs()` row dict |
| dataclass | `SegmentDef.default_strat: str \| None = None` (defaulted, same reason `waypoints` is — a non-default field TypeErrors every existing construction) |
| validation | `validate_definition`: if present, must be `None` or a non-empty string |
| seed | `default_strat` key on segment rows |
| reconcile | `tracking/defaults.py` passes it on insert AND on the non-dirty refresh |

`service._load_segment_defs` builds `SegmentDef` from
`dataclasses.fields(SegmentDef)` against the db row dict, so adding the field
in both places wires the load path with no third edit.

### 2. The corpus stamps it in one place

`tools/build_defaults_seed.py::_movement_row` already asserts that every
movement is route-scoped and Castle Movement *by construction* — the default
strategy joins that uniformity:

```python
return {..., "guards": ROUTE_SCOPED, "category": CASTLE_MOVEMENT,
        "default_strat": STANDARD_STRAT}
```

`STANDARD_STRAT = "Standard"` lives in `tools/corpus_vocab.py` beside the
other shared vocabulary constants. `corpus_legacy.SEGMENTS` (hand-written
rows) is untouched, so the 10 trick segments get no default.

`data/defaults.seed.json` is regenerated by the tool — never hand-edited.
`tests/test_build_defaults_seed.py` (the `--check` drift guard) pins it.

### 3. The fallback lives in the projector, in two lines

`Projector.strat_by_segment` is the single dict every consumer reads — the
attempt's `strat_tag` at close time (`projection.py` caveat 6), the
`strat_tag` property, the section banner, `segment_targets`, the target
payload. So the default is applied by pre-seeding that dict rather than by
touching six call sites:

```python
# __init__
self.strat_by_segment = {d.id: d.default_strat
                         for d in (segments or []) if d.default_strat}

# strat_set handler, segment branch
self.strat_by_segment[seg_id] = ev.payload.get("strat_tag") or default
```

Consequences, all intended:

* a movement's attempts are tagged `"Standard"` from the first run, with
  nothing written to the journal on the user's behalf;
* a journaled pick of a different strategy overwrites it and sticks
  (re-derived identically on every replay — the dict is rebuilt from the
  defs each time a `Projector` is constructed);
* a **falsy** pick — a `null` `strat_tag`, whether from an old journal entry
  or any future path — falls back to the default instead of unsetting it.
  That is the "no strat is not a valid option" rule enforced in the data,
  not only in the dropdown.

Per-attempt reclassification (`attempt_strat_set`, caveat 16) is unaffected:
`strat_overrides` still shadows the stamped value, including back to `None`
for one historical attempt.

### 4. "— no strat —" disappears where a default exists

* `views._seg_strategies` puts `default_strat` at the head of the segment's
  strategy list, so it is always an option even before any attempt or
  registration exists under it.
* The segment section payload carries `default_strat`.
* `ui/components/stratpicker.js` gains `allowBlank` (default `true`). When
  `false`, the `<option value="">` sentinel is not rendered.
* The segment card and the attempt-row reclassify picker pass
  `allowBlank=${!section.default_strat}`. One shared component, so both
  pickers change together and cannot drift (the reason StratPicker exists).

Stars and user-created segments render exactly as today.

### 5. Existing databases

No repair migration. All 55 movement rows are seeded (`seed_key` set) and
untouched (`seed_dirty=0`), so `reconcile_defaults` refreshes them from the
new seed at the next startup.

**Known gap, deliberate:** a movement the user has *edited* (`seed_dirty=1`)
is protected from the refresh by the seeded-row contract and will not gain
the default. "Reset to default" is the existing escape hatch. Special-casing
this would mean writing through a dirty row, which is the one thing that
contract exists to prevent.

## Star ↔ segment parity (CLAUDE.md rule 11) — deliberate asymmetry

This ships for segments only. The reason: a default hangs off a seeded
*definition row*, and stars have no definition row — they are intrinsic to
the game, enumerated in code, with nothing to attach a default to. Star
strategies also genuinely vary per star (48 entities in the rank standards
carry "Standard", but 54 do not), so there is no defensible value to default
to. If stars ever gain seeded per-star config, this is the field to add.

Recorded here and in `.claude/rules/tracking-storage.md` as rule 11 requires.

## Testing

| Area | Assertion |
|---|---|
| corpus | all 55 movement rows carry `default_strat="Standard"`; all 10 legacy rows carry none; `--check` drift guard still passes |
| db | v13 migration adds the column; insert/update/read round-trip it; an old db upgrades without loss |
| segments | `SegmentDef` defaults to `None`; `validate_definition` rejects a non-string, accepts absent/`None` |
| reconcile | a fresh insert and a non-dirty refresh both carry the default; a dirty row keeps its old value |
| projection | an attempt on a defaulted segment closes with `strat_tag="Standard"` with no `strat_set` in the journal; an explicit different pick wins; a `null` pick falls back to the default; a segment with no default is unchanged (`None`) |
| views | the segment section lists the default in `strategies` and reports `default_strat`; `last_strat` reads "Standard" |
| UI | rendered picker for a defaulted segment has no blank option and shows "Standard" selected; a star's picker still has it |

## Non-goals

* No UI to author or clear a default (corpus-only).
* No back-fill of `strat_tag` on already-recorded attempts — history stays
  as it was recorded; per-attempt reclassification already exists for that.
* No change to rank standards; a movement is still unranked until standards
  exist for it.
