# Memory reads & detectors — where to change what

Full detail, evidence and history: [docs/rules/memory-detectors.md](../../docs/rules/memory-detectors.md) — read it when changing a detector's timing, hold or identity rule, a calibration constant, or when a live report contradicts what a detector publishes.

## Star timing — the x-cam, the settle wait, and the evidence for both

- A star is timed at the X-CAM: `STAR_DANCE_ACTIONS` entry. A midair grab is HELD through `ACT_FALL_AFTER_STAR_GRAB`; `frame` is the x-cam, `grab_frame` the touch. A grab that never reaches a dance (savestate, level change, reset, 300-frame backstop) still journals, with `igt_timed_at: "grab"`.
- The number is Usamune's result write landing at or after the x-cam (`IgtClock.igt_at_xcam`). Publish on AGREEMENT with our derivation, **never on "the first write"** (`AGREEMENT_FRAMES` 1; `PUBLISH_WAIT_FRAMES` 12 backstop). The watch runs on to `RESULT_SETTLE_FRAMES` (45, pinned inside `StarGrabDetector.RESULT_SETTLE_BRACKET` by `tests/test_star_grab.py`) and emits `star_time_corrected`, folded into the grab by `projection.time_corrections`. **Never widen that window "for safety"**: leaving the course zeroes the store.
- `igt_source: "counter"` on a star row is the legality signal. Across a subarea, `IgtClock.carried_igt_at_xcam` adds the banked leg only across an edge into a NON-1 area, and `_answer` must recognise Usamune's early echo of our subarea-local counter (`_PendingGrab.subarea_local_igt`). `LEVEL_LOAD_TAIL_FRAMES` (60) ignores a course entry's own area settling.

Detail: [docs/rules/memory-detectors.md#star-timing--the-x-cam-the-settle-wait-and-the-evidence-for-both](../../docs/rules/memory-detectors.md#star-timing--the-x-cam-the-settle-wait-and-the-evidence-for-both).

### The 45-frame wait is GONE (2026-08-04, task 0083) — we own the epoch, Usamune owns the tick

`detectors/counter_epoch.py`'s `EpochTracker` is the one door for "did this counter restart belong to the level or the player": it BANKS a leg at level-caused restarts, ZEROES at player-caused ones, and accumulates any number of legs; the whole star is `banked + counter`. `_usamune_answer` asks two questions: *final?* (a midair grab needs a write strictly after the x-cam) and *best known?* (the loose bracket) — never conflate them. Detail: [docs/rules/memory-detectors.md#the-45-frame-wait-is-gone-2026-08-04-task-0083--we-own-the-epoch-usamune-owns-the-tick](../../docs/rules/memory-detectors.md#the-45-frame-wait-is-gone-2026-08-04-task-0083--we-own-the-epoch-usamune-owns-the-tick).

## A grab publishes one frame later since the loop stopped double-polling

Detectors run ONCE per game frame, so `published_after` reads 1 at the earliest; the recorded time is unchanged. `tests/test_detector_cadence_parity.py` drives the real chain at both cadences with a WHITELIST: anything else moving with the cadence is a real behaviour change. Journal replay cannot test cadence — it never re-runs a detector. Detail: [docs/rules/memory-detectors.md#a-grab-publishes-one-frame-later-since-the-loop-stopped-double-polling](../../docs/rules/memory-detectors.md#a-grab-publishes-one-frame-later-since-the-loop-stopped-double-polling).

## The entrance touch names where it leads, on its own frame

- `warp_entered` is the ENTRANCE TOUCH; `frame` and the igt trio stay the touch's however late it publishes. A painting/portal writes `sWarpDest` at the touch; a pipe/hole ~20 frames later. `sWarpDest` counts as live only if it CHANGED within `FRESH_WINDOW_FRAMES` (4) (`type != 0` is not freshness); the first value after start-up is unstamped (= hold).
- Release order: struct written → level edge → area edge → bounds publishing `to: None`: backward `global_timer`, a FROZEN countdown (op still armed past `RIDE_WINDOW_FRAMES` with the counter frozen `PAUSE_CONFIRM_FRAMES`), a CANCELLED ride (`DELAYED_WARP_TIMER` separates cancel from completion), `HOLD_CAP_FRAMES` 240. **`pending_warp_op` going quiet is never a release** — it clears mid-fade. A second touch supersedes a held one, bounded by `RIDE_WINDOW_FRAMES`. Touches carry `released_by`/`held_frames`.
- SECOND in `main.build_detectors`, behind star_grab only (`tests/test_composition.py`). Historical rows lack `to`; `projection.warp_destinations` recovers it (`.claude/rules/tracking-storage.md`).
- BBH: `ACT_BBH_ENTER_JUMP` is in `WARP_ENTRY_ACTIONS` (spin excluded); the SPIN publishes `to = BBH_LEVEL`, the jump never does; the hold cap defers while the cage animation plays, bounded by `HOLD_ABSOLUTE_CAP_FRAMES`. `probe_warp_block.py --entries` is the instrument for an entrance that fires no touch; a movement that records nothing may be a missed touch. Never assert a value unknowable from RAM without watching it (`tools/probe_warp_block.py`).

Detail: [docs/rules/memory-detectors.md#the-entrance-touch-names-where-it-leads-on-its-own-frame](../../docs/rules/memory-detectors.md#the-entrance-touch-names-where-it-leads-on-its-own-frame).

## The spawn point is the identity

A landmark is keyed on `(level, area, behaviour, home)` with `OBJECT_HOME_POS` — never the pool slot or ordinal, never the live position; the area is part of the key. A scriptless object (home `(0,0,0)`) never moves, so `core/landmark.py::where` uses its position; `nameable` is true when that coordinate is non-zero; an object with NEITHER is refused. No static-kind allowlist and no velocity discriminator. Detail: [docs/rules/memory-detectors.md#the-spawn-point-is-the-identity](../../docs/rules/memory-detectors.md#the-spawn-point-is-the-identity).

## Recipes

Adding an event type, a dust trick, or locating an unknown memory value. Rules that bite: a held emit is published before every detector that closes an attempt (`build_detectors`' docstring); new memory fields go through addresses.py (+VERIFY); **print a new field on `tools/verify_addresses.py`'s live frame and star lines**; dust timing is `frames_late = visible_landing_frames - 1` — do NOT re-derive it from the spec; a THIRD dust stat family generalizes counts into a keyed structure. Detail: [docs/rules/memory-detectors.md#recipes](../../docs/rules/memory-detectors.md#recipes).

## A spawn names its subarea and its spawn point

`spawned` carries `area` and `spawn_node` (`sWarpDest`'s nodeId, taken only when the struct's level+area match the spawn's, else null — `spawn.py::spawn_node_from`, test_spawn.py). VERIFY: two pyramid entries must journal two values. Label via `addresses.subarea_name`; `synthesize._spawned_params` carries both (`tests/test_spawn_subarea.py`). Detail: [docs/rules/memory-detectors.md#a-spawn-names-its-subarea-and-its-spawn-point](../../docs/rules/memory-detectors.md#a-spawn-names-its-subarea-and-its-spawn-point).

## A moment's time is per-kind

`Moment.display_lag` via `display_lag_for(kind)` is the one answer; `caused.py` goes through it too, and a caused kind raises rather than borrowing the door's number. Never flip one global offset. `tools/score_moment_clock.py` scores a screen reading against the RAW counter, one verdict per kind (`tests/test_score_moment_clock.py`). `segments.IGT_ARM_SKEW_FRAMES` stands. Detail: [docs/rules/memory-detectors.md#a-moments-time-is-per-kind](../../docs/rules/memory-detectors.md#a-moments-time-is-per-kind).

## A lingering pointer must never lend its name — one watch, two detectors

`core/landmark.py::EngagementWatch` is THE answer to "is this engagement fresh"; a new reader of `landmark_at` goes through it. `moment.py` gates both ends (`ENGAGE_FRESH_FRAMES` 4 / `ENGAGE_ADOPT_FRAMES` 6); stale degrades to no landmark, never a foreign name. Only kinds with `Moment.needs_fresh_engagement` (the textbox) are gated — an object interaction's pointer is authoritative even unchanged. No per-kind behaviour allowlist. Forward-only. Detail: [docs/rules/memory-detectors.md#a-lingering-pointer-must-never-lend-its-name--one-watch-two-detectors](../../docs/rules/memory-detectors.md#a-lingering-pointer-must-never-lend-its-name--one-watch-two-detectors).

## A textbox is timed at the BOX, not at Mario's turn toward the NPC

`Moment.open_states`: NPC dialogue fires when `mario_action_state` reaches `addresses.BOX_OPENS_AT_STATE`, watched every poll. `ACT_WAITING_FOR_DIALOG` never opens the box by itself. `DIALOG_ACTIONS` is untouched and `anchors.py` reads it directly — keep them decoupled (tested). Forward-only. `ACT_READING_SIGN` is unhandled: it needs its own address discovery and live gate, not a line added here. Detail: [docs/rules/memory-detectors.md#a-textbox-is-timed-at-the-box-not-at-marios-turn-toward-the-npc](../../docs/rules/memory-detectors.md#a-textbox-is-timed-at-the-box-not-at-marios-turn-toward-the-npc).

## Round 4: two dialogue kinds, two measurements

NPC: box-open gate (threshold 8), `Moment.gated_display_lag[ACT_READING_NPC_DIALOG] = 2` → `counter + 3`. Automatic: absent from `BOX_OPENS_AT_STATE` = plain entry edge, `display_lag = -1` → `counter + 0`; never gate it on an unmeasured threshold. `ACT_WAITING_FOR_DIALOG` carries an explicit `None`. Doors stay `counter + 2`. `tools/probe_textbox.py` settles where automatic dialogue's box opens. Detail: [docs/rules/memory-detectors.md#round-4-two-dialogue-kinds-two-measurements](../../docs/rules/memory-detectors.md#round-4-two-dialogue-kinds-two-measurements).

## A moment's landmark settles one poll late

The event is built on the action edge (frame, igt, ordinal, action) but its LANDMARK is re-read on the NEXT poll. The settle is refused (edge reading stands) on a backward `global_timer` or a level/area change. A held event describes the past and is published before anything describing the present. Detail: [docs/rules/memory-detectors.md#a-moments-landmark-settles-one-poll-late](../../docs/rules/memory-detectors.md#a-moments-landmark-settles-one-poll-late).
