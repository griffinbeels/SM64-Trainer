| Poll loop, attach retry, layout sanity, session pause | `server/poller.py` — also SYNTHESIZES `game_reset` on reattach: an F1 console reset makes RDRAM briefly implausible → detach nulls `_prev` → the backward-into-boot jump is lost, so on reattach it keeps `_last_timer` across the gap and emits `game_reset` when the timer dropped from ≥ BOOT_TIMER_MAX into it (live gate 2026-06-15; test_poller.py). Also carries the tracker's **frame heartbeat**: `on_frame` (constructor-injected, `main.py` passes `TrackerService.settle_frame`) is awaited with the live `global_timer` after each tick's events, so a judgement the matcher deferred by one frame is delivered by the CLOCK instead of by whatever the player happens to do next — standing still inside a course journals nothing, and that cost a correct segment cancel 27.7 s of screen time (`.claude/rules/tracking-storage.md`, the one-frame defer). | What the UI DREW (the observation log) | `core/uilog.py` (store, `data/ui_log.jsonl` beside the journal) + `POST /api/uilog` in `server/app.py`. The route lives at the composition surface for the same reason `/api/pause` does — it stamps the frame from `poller.latest`, so a UI observation lands on the clock the journal is indexed by instead of on the browser's idea of it. Three properties make it trustworthy as an instrument, and each has its own test: it can never break the page it observes (an unknown body is DROPPED, never a 500 — a stale tab or a second app on the port must not be able to raise), it survives its own crash (a torn final line is skipped, not raised on), and it stays bounded (trimmed to the newest `MAX_RECORDS`; every string and list clipped, since the body is free-shaped and comes from a browser). Client half + why it reads the DOM: `.claude/rules/ui-core.md`. Read it back with `tools/what_happened.py`, which interleaves it with the journal — and treat an EMPTY log as the finding it is: the page posts these itself, so silence means the open tab is running old JS |

| MARELO scope surface (aggregate/history/exclude/ack) | `server/ranks_api.py` (same file, built on top of the ranks CRUD above — scoring/aggregation itself lives in `ranks/scoring.py`+`ranks/scopes.py`+`ranks/history.py`+`tracking/marelo.py`, see `.claude/rules/ranks.md`) — `GET /api/marelo` (`?scope=`, defaults to `_active_scope` = the focus route else Overall, so there is no second scope control to keep in sync; unknown scope → `404` deliberately, so a stale route id in a client reads as gone rather than silently becoming a different rating), `GET /api/marelo/history`, `GET /api/marelo/scopes`, `GET /api/marelo/summary` (the always-visible op.gg-style chip row: `overall` + every `category`-"Main Categories" route + the active scope, capped at 6 — `_score_scope` factors the pure groups→aggregate→per-entity-tier path OUT of `_build_marelo` specifically so this endpoint can reuse the scoring without also running `_build_marelo`'s watermark side effects; loops `_score_scope`, never `_build_marelo`), `GET /api/marelo/exclusions` (the raw set, so the strategy modal's "include in ranking" tick can read ONE entity's state — it can open on an entity with no standards yet, which is in no scope and therefore in no `/api/marelo` payload), `POST /api/marelo/exclude` (reversible — excluded entities stay in the response's `entities` as inert rows: `_append_excluded_rows` re-resolves scope membership a SECOND time with NO exclusion filter to find them again for display, without letting them back into `aggregate`'s numerator/denominator), `POST /api/marelo/ack` (body is `{scope,key}`; a missing scope is `400`, and so is the `{entity,key}` form this accepted until task 0012 — see below). **FOUR** distinct watermark operations, all in `_build_marelo`/`TrackerService`: `ack_celebration` RAISES and broadcasts (UI-driven only — fired once the celebration has actually been shown, never on a bare GET; the broadcast is what makes the OTHER open client dismiss the same one), `sync_watermark` LOWERS on every GET (follows a drop down so re-climbing celebrates again), `seed_watermark` CREATES on a scope's first-ever rank (no-op once the key exists, so the first view of a scope never celebrates the user's whole history at once), and — since 2026-07-28 — `absorb_watermark` RAISES silently, with no broadcast, because nothing was shown for another client to dismiss. `/api/marelo/summary` triggers NONE of them, by construction (`_score_scope` never calls them). **Arriving at a scope is not earning a rank in it** (live report: "I just swapped the route around at the top over and over again… Swapping between routes like that should never trigger any rank up"): until that fix only `ack` could raise a watermark, so every scope accumulated a rank-up it had never DISPLAYED and discharged it the first time the user looked at that scope — 48 routes, 48 queued celebrations; measured on the live db, 3 of 7 watermarked scopes fired on sight, two of them tier crossings. Two rules cover it, each closing a hole the other cannot: only the ACTIVE scope may celebrate (so browsing the Rank tab's scope chips never fires one — looking at a rating is not earning it), and `note_active_scope` makes the FIRST build after the active scope changes absorb instead. The accepted cost, which was the user's call and not an assumption: scopes overlap, so a rank-up genuinely earned on a route you were not focused on is absorbed silently and never celebrated. `marelo_changed` is broadcast-only (no journal entry). **Entity-level celebrations were REMOVED** (task 0012, 2026-07-26) — `_entity_scores`, `_entity_celebrations`, `TrackerService.entity_watermarks`/`sync_and_seed_entity_watermarks`/`ack_entity_celebration`, the `entity_rank_watermarks` KV and the `{entity,key}` ack arm are all gone, and `/api/marelo` no longer scores the full rankable corpus a second time for a non-overall scope. A star's or segment's own rank-up is performed live by the rank banner climbing in the UI (`.claude/rules/ui.md`'s climb row), so there is nothing to hold and nothing to ack; an entity ack is now a 400 rather than a silent no-op. The SCOPE trio (`sync_watermark`/`seed_watermark`/`ack_celebration`) is unchanged. |
