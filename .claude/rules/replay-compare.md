# Replay, compare, compilation — where to change what

| To change... | Edit |
|---|---|
| Replay orchestration (attach loop, source wiring, ring, idle gate) | `replay/recorder.py` + player-input tap `replay/activity.py`; `replay/clock.py` is THE QPC↔UTC contract. Routes BOTH streams into the single AV sink (`_on_frame`→`submit`, `_on_pcm`→`submit_audio`); the in-process `SegmentWriter` is a no-ffmpeg fallback only. Idle THROTTLES capture grabs (`is_idle` → `video.set_idle_check`) AND discards segments; the ring byte-cap is free-disk-gated (`ring.effective_cap`) |
| Video capture (DWM surface primary; GDI fallback) | `replay/video.py` + `replay/_dwm.py` — docstrings carry the PJ64 capture pathology and the no-user32-on-grab-thread rule; `grab_period` trickles grabs to 8 Hz while idle (kills the ~2 GB/s frame-alloc churn; ffmpeg feeder untouched so resume stays seamless); active capture oversamples (fps×2 DWM / fps×1.5 GDI) — a system-lag suspect, see docs/architecture.md. PJ64 window locate in `replay/window.py` (`find_window`/`pick_window`/`WindowInfo`, wired via `main.py` `window_finder=`) |
| WHEN each game frame happened (the clip's frame map) | `replay/frameclock.py`, THREE series, per-slot rank presents > feeds > edges. The PRESENT series (v4, item 30): the poller watches PJ64's host-side present counter (hunted per session by `memory/present.py`; the poller's `_watch_presents` marks each tick with the frame read on the same poll tick, skipping the unobserved first) and `derive_present_frames` turns ticks into frames — within a run frame = count + shift (shift from the run's delta FLOOR − `PRESENT_LAG_FRAMES`), so the logic→present wobble lands in the tick TIMES; a re-present train (logic frozen, counter ticking) derives nothing (timer-span guard + tail-trim, both mutation-proved). The FEED series (v2): `recorder._on_frame` tags each captured picture at capture with `capture_tag(utc_of(ts_100ns))` — the RAM frame AND the picture's own composition time; the tag rides `FfmpegAvSink.submit` to the feeder and `mark_feed` records what was fed; the presents lookup keys on that composition time. The EDGE series (v1): the poller marks every frame edge's wall time (250 Hz). v2 exists because edges + ANY constant lag measured ±1 two-sided on clip 741 (8/44 exact); v4 exists because v2 still held the present wobble (24/53 exact on the same scorer). Two measured constants live in frameclock.py and are re-measured by the A-icon template method, never guessed: `MAP_WALL_BIAS_S` (the encode chain answers half a slot late, uniformly -- attempt 2147: feeds 10/10 at -1 slot) shifts every slot's lookup wall, and each run's PHASE is normalized against the poller's edge series (each hunted counter ticks at its own pipeline point; two sessions measured 17 ms apart), with `PRESENT_TICK_TRAIL_S` only the no-edges fallback. **THEN the map is held to ONE ANSWER PER PICTURE and checked against the clip's own pixels** (`replay/mapalign.py`). `picture_runs` finds each distinct picture in the footage (160x120 grey, mean-diff >= 0.35) and `quantised` gives every video frame of a run the same answer -- his ruling 2026-08-28, "if there's duplicated frames, input timeline should be identical for the sequential duplicated frames", measured on his clip 4374: 257 pictures carried two different frames before it and 0 after. TWO rules, and the second was found by his stepping: every video frame of one picture answers the same, AND **consecutive PICTURES are consecutive FRAMES** -- holding the boundaries alone left the map's own irregular advance untouched (his clip 4441: 230 pictures sharing a frame with the next and 225 skipping one; three different pictures all read frame 7, then a jump to 9). Each picture is pushed to the nearest series rising by >=1 per picture (`_rising`, pool-adjacent-violators on value-minus-index) -- a least-squares fit, NOT a walk that bumps each past its predecessor, because a dip is evidence about all its neighbours and bumping would drag every later picture up to satisfy one bad reading (mutation-proved by exactly that case). After it: 0 shared, 1,157 of 1,163 advancing by one, clip span unchanged. Rising by MORE survives where the map says so, since the capture really does miss frames. The runs supply the BOUNDARIES, the map still supplies the ADVANCE (numbering pictures consecutively would drift by every game frame the capture missed -- 428 pictures for ~478 frames on that clip). It runs even when the aligner refuses, because it needs nothing but the pictures. **THEN the map is checked against the clip's own pixels and shifted onto them** (`replay/mapalign.py`, 2026-08-28): the constants above estimate a journey (logic -> present -> capture -> encoded slot) that RAM cannot measure, and four rounds of setting them by hand each landed somewhere else (-2 slots, +1, -3, every one verified live). Usamune's stick digits are IN the footage and the input track says what they should read, so `align_clip` fits per-glyph ink weights at every candidate offset and the best fit names the error; `ReplayService._align_to_the_footage` applies it. The verdict gate judges the peak against the best offset OUTSIDE its own +-1 neighbourhood (`gate`), because on a quantised map the neighbour is near-equivalent by construction -- the neighbour-inclusive gate refused 4441's clean peak on a 0.007 tie and the clip ran a frame ahead (2026-08-29, pinned on that clip's real curve). The correction lands in the FRAME domain (`frame_corrected`, round(slots/2) on every value) so an odd slot shift can never re-split pictures. A clip whose digits cannot be read inherits the MEDIAN anchor other clips measured (`AnchorStats`, data/mapalign_anchor.json, min 3 measurements, newest 40 kept) -- calibrate-once made continuous; `frame_map_learned` marks it. It REFUSES (display off, too little track, no clear winner) rather than shift by a fitted nothing -- the sidecar's `frame_map_aligned`/`frame_map_offset`/`frame_map_fit` say which happened, and the aligner is injected from `main.py` because it needs the input track. Same code as `tools/score_frame_map.py`'s verdict, so the tool cannot drift from what extraction did. `ReplayService.view()` writes the sidecar's `frame_map` + `frame_map_source` ("presents"/"feeds"/"edges"/"mixed") at extraction; a save keeps both; `tools/score_frame_map.py` prints the source with its verdict. Never absorb a per-clip desync into a new constant — score it with the tool; the offset is only the fallback for pre-map clips |
| The PIXEL-READ map (v3, built, NOT wired) | `replay/pixelmap.py` — reads Usamune's own display out of the footage (value-field fingerprints, weighted templates learned from the v2 prior's holds) and fits the map to the reads with a banded monotone DP; `InputsService.pad_lookup` is its data door and `tools/probe_pixel_read.py` its gate. Wire it into `ReplayService.view()` ONLY when the probe's training accuracy reads ≥99% (it read 84%/49% Y/X on clip 778, 2026-08-23 — the READER is the bottleneck, and at that accuracy a fit can move slots wrongly, which violates the 100% ruling harder than v2's honest ±1). Two dead ends recorded in the module docstring: nearest-change snapping (no-op under dense stick changes) and button-icon offset curves (anchors cannot see between themselves; grass reads as the B icon). 'Values the track never held: 0' is the measured proof 100% stays reachable |
| A+V single mux (ffmpeg subprocess) | `replay/ffmpeg_sink.py::FfmpegAvSink` — ONE ffmpeg muxes video (stdin) + audio (named pipe) on ONE wall-clock: `-use_wallclock_as_timestamps` before each input, `-fps_mode cfr` video, `-af aresample=async=1` audio → combined A+V MPEG-TS segments. THIS is the two-clock-drift fix (memory `replay-av-drift-two-clocks`); feeder pacing is not load-bearing. Segment→UTC = anchor-at-first-frame + CSV offset RELATIVE to the first segment. In-process fallback (no ffmpeg, legacy two-clock): `replay/encoder.py`. Encode QUALITY comes from `replay/config.py::video_quality_args`, not here |
| GC policy (stop-the-world watchdog + gen-2 idle collector) | `replay/_gcwatch.py` — freezes the startup heap, disables AUTO gen-2, runs manual `gc.collect(2)` during idle with a 5-min never-idle backstop; `arm(is_idle=recorder.is_idle)` from `server/app.py` lifespan |
| Audio (per-process tap primary, endpoint-by-pid fallback, RT-safe pump, deaf-stream watchdog) | `replay/audio.py` + `replay/_system_audio.py` — `ProcessAudioSource` (proctap / WASAPI **process** loopback) is PRIMARY so a clip carries the game and nothing else on the desktop; `SystemAudioSource` (device loopback of the endpoint hosting the pid's session) is the FALLBACK and records everything sharing that endpoint. Both factories take the **pid** (`recorder.py`), both feed the same `AudioPump` — a PURE RT-safe handoff (PCM → `recorder._on_pcm` → sink's audio pipe; no sample-count placement / silence injection, ffmpeg's wallclock+aresample own timing) — and both self-heal through the shared `DeafStreamWatchdog`. proctap yields float32; int16 is the one format on the wire to the sink. `proctap` must stay in `tools/build_exe.py::COLLECT` or the frozen exe silently degrades to desktop-wide capture. **`tools/probe_audio_isolation.py` is the live gate**: two ffplay children playing 440/880 Hz at once, only the 440 process captured — one tone proves the tap is alive, never that it is isolated (device loopback passes a one-tone test perfectly). Rejected alternatives and the deaf-tap escalation policy: docs/architecture.md audio facts |
| Clip extraction (ffmpeg cut of A+V segments) | `replay/extract.py` — pure ffmpeg cut: `concat:` the covering segments, accurate-seek the span, re-encode video (0.5s GOP) + faststart, `-c:a copy`. Coverage holes clamp to the contiguous run containing the span start (`contiguous_run` / `_joinable` — a FRAME-SIZE change breaks a run too). Segments carry their `dims` (`SegmentInfo`, stamped per ffmpeg child). Quality from `replay/config.py::video_quality_args` — the cut must be TRANSPARENT w.r.t. its segments |
| Encode quality (ring sink + clip cut) | `replay/config.py` — `VIDEO_CQ`/`VIDEO_CRF` + `video_quality_args(codec, stage, maxrate)`, THE registry both encoders read. Constant-quality, never a bare bitrate (the "blurry recording" bug: extractor with no rate control fell back to ffmpeg's ~2 Mbps default, fixed 2026-07-23). Raising quality costs ring disk — `VIDEO_CQ` is the one knob |
| Clip save/extract/settings orchestration | `replay/service.py` — `ReplayService`: attempt→span→clip→save + user settings + `available_attempt_ids()`; `_coverage_notices` answers whether the clip is missing any of the ATTEMPT (`starts_mid_attempt` / `ends_early`, from the timestamps) as opposed to merely a short run-up -- `replay.js` drew its "Starts mid-attempt" warning off the coarse `truncated` flag until 2026-08-28, which put an alarm on an ordinary reset ("but... I just reset as normal? What does this even mean?"); `truncated` still ships and still means what it meant; same LookupError/ValueError/RuntimeError→HTTP taxonomy as api.py |
| Single-RECORDER guard (machine-wide) | `core/recorder_lock.py` — fixed temp-dir file lock so only ONE instance captures PJ64, even across exe + dev servers in separate worktrees (different data dirs → per-db instance_lock does NOT coordinate them; two recorders doubled GPU/encode/audio load, live 2026-06-15). `recorder.py` acquires in `_begin_capture` (can't → viewer-only, auto-takeover next attach cycle), releases in `_teardown_capture`. Injectable (`recorder_lock_factory`); tests redirect the path via conftest |
| Side-by-side compare (import jobs, CRUD, view, serve) | `compare/service.py` — composes `compare/importer.py` (yt-dlp/copy/upload-bytes → ffmpeg-normalize → content-addressed cache in `core/paths.compare_cache_dir()`, dedup = "load once"; atomic publish via `.tmp-<name>`+os.replace) + `storage/db.py` comparisons (migration v10). **Wired in main.py on ffmpeg alone, never gated on the db** (task 0053): a boot that loses the instance-lock race (the reload handoff — the old app's replay teardown can outlive the new boot's bounded wait) used to skip the router entirely, so every compare call 404'd and the tab read as "videos don't load" with nothing in any log; the service reads `tracker.db` per call, answers 503 until the reattach loop lands the db, then works with no restart (pinned by `tests/test_composition.py::test_dbless_boot_still_mounts_compare_and_compilation`, which covers compilation's identical gate). The UI half of the same incident: `compare.js` refetches the view on tab activation (a fetch that failed during a restart otherwise stuck all session — re-picking the same run is a state no-op) and every import/view failure now renders (`cmpError` / job error state), never a silent swallow |
| Failure compilation (build + job) | `replay/compilation.py` — `CompilationBuilder` reuses `ClipExtractor` per window then ONE concat-filter ffmpeg pass scales+pads to a common canvas (probed from the finale clip) and re-encodes to one MP4 (single clip → copy); `CompilationService` runs it as a polled daemon-thread job (mirrors `CompareService`), output → `compilations_dir()` |
