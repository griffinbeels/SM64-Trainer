# Replay, compare, compilation — where to change what

With the installed layer (the trainer's renderer plus the capture wrapper) the
one recording route is `sourcefactory.py` → `gpucapture.py`/
`gpucapture_session.py` → GPU delivery and the isolated NVENC helper →
`gpumedia.py`/`packetmux.py` → shared fragments. `gpudemand.py` owns the
independent lease; `gpuretry.py` bounds failed activation. Without the layer
the recorder falls back to the desktop grab (`video.py` + `ffmpeg_sink.py`)
with no stamps. The raw FrameStream/ReadScreen path was deleted on 2026-09-16.
Current ownership, timing, setup and hardware limits belong to
[Renderer GPU recording](../../docs/replay-gpu-runtime.md).

| Replay orchestration (attach loop, source wiring, ring, idle gate) | `replay/recorder.py` + player-input tap `replay/activity.py`; `replay/clock.py` is THE QPC↔UTC contract. | THE PAD READER -- Usamune's input display read out of a clip's pixels | `replay/padread.py`, an OFFLINE INSTRUMENT since 2026-09-05, not part of extraction. Six glyph cells per picture (letter/d1/d2 on the U-D line and the L-R line), one template per painted GLYPH weighted to the pixels the font paints (`ink_mask`) where the exemplars agree; a cell reads only by a clear margin (`DIST_MAX`/`MARGIN_MIN`) else it is UNKNOWN -- there is no blank class, so an empty cell can never be read as a glyph. A shipped reference alphabet (`data/pad_glyphs_us.npz`, learned off 7 min of ring footage and verified against the track) reads first, then the clip re-learns its own glyphs at its own scale. `enforce_grammar` fixes its commonest error, found map-free: Usamune prints an axis as a bare `0` or a letter beside 1..99, so a letter beside magnitude 0 is impossible -- 8.9% of readings on clip 6510 were exactly that, because `ink_mask`'s bright clause counts a white sky as ink. WHY IT LEFT EXTRACTION: it answered "does the timeline hold the pad the game held", which the capture layer's own copied pad answers exactly and for free, and it answered it at 82-94% on three clips the oracle certified exact -- every sampled disagreement its own digit confusion (L13 for L12, U83 for U82, a dropped letter). At extraction it was also reading almost nothing (65 of 477 cells on 7267) while costing ~3 s a clip. WHY IT STAYS: `tools/score_pad_read.py` and `tools/score_picture_offset.py` are the instruments that settle a picture-vs-pad question, `replay/oracleread.py` borrows its glyph machinery, and reading the pad off PIXELS is how CONSOLE input capture would work, where no RAM is readable. |
| The capture layer and installer | `plugin/gfxwrap/gfxwrap.c` is the wrapper Project64 selects (`SM64 Trainer v1.0`); it loads the trainer's renderer named by `sm64_trainer_gfx.ini` (`GLideN64_SM64Trainer.dll`, LINK's GLideN64 v4.2 plus the overlay in `plugin/gfxwrap/`), copies the address table at ProcessDList and stamps the renderer's GPU pictures. `replay/pluginsource.py::table_for` takes addresses from the selected layout; decoding reuses `inputs/frame.py`. `core/capturelayer.py` installs both DLLs and the ini under consent, remembers the plugin it replaced for undo, compares installed files with the bundle by embedded build id, and refuses replacement while PJ64 is running. `tools/build_plugin.py` builds the wrapper and the 64-bit encoder helper; `tools/build_renderer.py` builds the renderer from the pin in `renderer/`; `tests/test_bundled_natives.py` pins that all three bundled files match the tree. | The picture feed and retained media clock | `replay/media.py::MediaRun` owns encoder identity/origin. | The PICTURE LEDGER (item 40 — capture's own per-picture record, the map's FIRST source) | `replay/ledger.py` — his spec 2026-08-28: "at every single frame of gameplay we have access to all the memory addresses and data in-game… embed each frame with extra information… extend the frame-by-frame information storage at any point". On the GPU route `gpumedia.py` passes the native worker's selection result to `PictureLedger.observe_result`; on the desktop grab `recorder._on_frame` passes every grab to `PictureLedger.observe`. Both dedup by EXACT equality of a stride-8 sample (desktop-era cost: 93 µs/grab at 1600×1224, ~1.1% of a core at 120/s) and records one row per DISTINCT picture: composition time, RAM frame, plus every registered stamp (`ledger.stamps["name"] = callable` — ONE line extends the record). At extraction the clip's slice of those rows becomes the sidecar's `picture_ledger` — the durable per-frame record, stamps included — and `feed_map` joins it to the encoded frames. `observe()` never raises, so a ledger bug cannot cost capture. Torn grabs (a mid-update surface copy; 118 of 647 row gaps under 20 ms on attempt 4518) fold into their present row via `MIN_ROW_GAP_S`. **Debugging ANY timeline-vs-video report starts with `tools/inspect_timeline.py`** (item 44): `--frames` prints, per panel frame, the track pads, the map's slots and the ledger rows with their stamps; `--audit` walks the whole clip (row rate, torn pairs, stamp-vs-map residual stretches). The panel's FRAME readout is 0-based = the track axis |
| A+V single mux (ffmpeg subprocess, desktop grab) | The GPU route never starts ffmpeg (see `packetmux.py`). The desktop grab configures `FfmpegAvSink.publish_fragments` before start: one timestamped NUT input, one encoder, one fragmented MP4 output. No tee or parallel TS recording. `fragmentindex.py` indexes completed units once; `fragmentstore.py` appends shared extents; `fragmentmedia.py` owns run/session retention and eviction-driven ledger pruning. Standalone sinks without a consumer, explicit CFR and no-FFmpeg fallbacks retain their previous contracts. Codec quality is still `config.py::video_quality_args`; active operation costs and limitations are in `docs/replay-pipeline-cost.md`. |
| GC policy (stop-the-world watchdog + gen-2 idle collector) | `replay/_gcwatch.py` — freezes the startup heap before capture activation, disables AUTO gen-2, and runs manual `gc.collect(2)` after proved capture retirement with the existing 5-min backstop; `arm(is_idle=recorder.can_collect)` from `server/app.py` lifespan. Retained automatic-idle footage and unproved cleanup are not GC-safe windows |
| Audio (per-process tap primary, endpoint-by-pid fallback, RT-safe pump, deaf-stream watchdog) | `replay/audio.py` + `replay/_system_audio.py` — `ProcessAudioSource` (proctap / WASAPI **process** loopback) is PRIMARY so a clip carries the game and nothing else on the desktop; `SystemAudioSource` (device loopback of the endpoint hosting the pid's session) is the FALLBACK and records everything sharing that endpoint. Both factories take the **pid** (`recorder.py`), both feed the same `AudioPump` — a PURE RT-safe handoff (PCM → `recorder._on_pcm` → the sink; on the desktop grab ffmpeg's wallclock+aresample own timing, while the GPU route places PCM with `audiopacing.py` and encodes AAC in PyAV, `gpuaudio.py`) — and both self-heal through the shared `DeafStreamWatchdog`. proctap yields float32; int16 is the one format on the wire to the sink. `proctap` must stay in `tools/build_exe.py::COLLECT` or the frozen exe silently degrades to desktop-wide capture. **`tools/probe_audio_isolation.py` is the live gate**: two ffplay children playing 440/880 Hz at once, only the 440 process captured — one tone proves the tap is alive, never that it is isolated (device loopback passes a one-tone test perfectly). Rejected alternatives and the deaf-tap escalation policy: docs/architecture.md audio facts |
| Replay View and explicit media export | Normal `ReplayService` View builds native headers and input metadata over existing shared sample bytes; `server/replay_range.py` serves seekable ranges under leases. Frozen descriptors preserve URL identity; optional future post-padding never extends the wait. `publication.py` materializes Save/PB atomically; `ClipExtractor` materializes explicit compilation windows. Old saved MP4 and legacy segment extraction remain supported. Native edit starts must equal a source picture PTS; see `docs/replay-fragments.md` for the audio-startup regression and proof limits. |
| Hardware selection (desktop grab) | Frame-exact GPU capture is NVIDIA NVENC only (`docs/replay-gpu-runtime.md`). PyAV's own NVENC/x264 fallback is separate; its codec availability cannot establish the child binary's capabilities. `main.py` selects after resolving the backend. Hardware verification limits live in [the operation audit](../../docs/replay-pipeline-cost.md#hardware-selection). |
| Encode quality (ring sink + clip cut) | `replay/config.py::video_quality_args(codec, stage, maxrate)` is the registry for ring, transcode and compilation. | Shrinking a saved replay after Save/PB | `replay/compress.py`: `shrink` encodes beside the clip and `prove`s it (picture count, ticks, the sidecar's `frame_times`, decoded audio, length, SSIM floor, a real saving); `adopt` swaps under the same name and writes the sidecar's `media` block; `SavedReplayCompressor` is the one low-priority worker `ReplayService` starts, queues after a save, and `touch`es on every saved-clip request so a clip being watched is not swapped; its `stop` (app close) ends the encode in flight and swaps everything already proven, and its `start` re-runs every job still owed. Working files (the staged MP4, its proof, and the job note `enqueue` writes BEFORE any work) live in ONE hidden folder, `<save root>/.compressing/`, never beside the clip: the folder he opens after a session holds his replays and nothing else. Quality is the `archive` stage of `config.py::video_quality_args`. Every candidate runs with picture reordering OFF: reordered H.264 passed ffprobe and lost a clip's last 11 pictures in Chromium (2026-09-18), so a new codec row needs the every-slot browser seek check, not an ffprobe diff. The sidecar's other keys are never rewritten. |

## Recipe: add a user-visible replay setting

Bounds row in `SETTINGS_LIMITS` + plumb `validate_settings`/`save_settings`/
`apply_settings_file` (replay/config.py) → live-apply + getter in
`ReplayService.update_settings`/`settings()` → field on `SettingsBody`
(server/replay_api.py) → input in the recording-dot panel
(`ui/components/replay.js` BufferSettings) → README settings lines → tests in
test_replay_{config,service,api}.py. Mirror commits 69bb83d / 29fd542.
Settings persist in `data/replay_settings.json` (a JSON overlay beats a db
migration for scalars); corrupt/out-of-range files lose to defaults so the
server always starts.
