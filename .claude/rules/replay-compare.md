# Replay, compare, compilation — where to change what

| To change... | Edit |
|---|---|
| Replay orchestration (attach loop, source wiring, ring, idle gate) | `replay/recorder.py` + player-input tap `replay/activity.py`; `replay/clock.py` is THE QPC↔UTC contract. Routes BOTH streams into the single AV sink (`_on_frame`→`submit`, `_on_pcm`→`submit_audio`); the in-process `SegmentWriter` is a no-ffmpeg fallback only. Idle THROTTLES capture grabs (`is_idle` → `video.set_idle_check`) AND discards segments; the ring byte-cap is free-disk-gated (`ring.effective_cap`) |
| Video capture (DWM surface primary; GDI fallback) | `replay/video.py` + `replay/_dwm.py` — docstrings carry the PJ64 capture pathology and the no-user32-on-grab-thread rule; `grab_period` trickles grabs to 8 Hz while idle (kills the ~2 GB/s frame-alloc churn; ffmpeg feeder untouched so resume stays seamless); active capture oversamples (fps×2 DWM / fps×1.5 GDI) — a system-lag suspect, see docs/architecture.md. PJ64 window locate in `replay/window.py` (`find_window`/`pick_window`/`WindowInfo`, wired via `main.py` `window_finder=`) |
| WHICH game frame each video picture shows | `replay/feedmap.py` resolves `(encoder run, source PTS)` to the exact captured occurrence. `replay/service.py` projects that row's own state into `frame_map`, `picture_ids`, `picture_igt` and `picture_states`; it does not substitute predecessor state. `ui/videopicture.js` owns the browser's presented mediaTime; `ui/frame.js` steps occurrence IDs in actual VFR slot order. Missing/colliding identities remain unknown. Fresh independently decoded timer, stick and button witnesses are pinned in `tests/test_replay_captured_state.py`; Griffin subsequently accepted live samples including a long WDW 100 Coins run. Read [the chain](chain-input-timeline-frame.md): a pad-stamp audit compares RAM/store values and is not independent pixel proof. |
| THE PAD READER -- Usamune's input display read out of a clip's pixels | `replay/padread.py`, an OFFLINE INSTRUMENT since 2026-09-05, not part of extraction. Six glyph cells per picture (letter/d1/d2 on the U-D line and the L-R line), one template per painted GLYPH weighted to the pixels the font paints (`ink_mask`) where the exemplars agree; a cell reads only by a clear margin (`DIST_MAX`/`MARGIN_MIN`) else it is UNKNOWN -- there is no blank class, so an empty cell can never be read as a glyph. A shipped reference alphabet (`data/pad_glyphs_us.npz`, learned off 7 min of ring footage and verified against the track) reads first, then the clip re-learns its own glyphs at its own scale. `enforce_grammar` fixes its commonest error, found map-free: Usamune prints an axis as a bare `0` or a letter beside 1..99, so a letter beside magnitude 0 is impossible -- 8.9% of readings on clip 6510 were exactly that, because `ink_mask`'s bright clause counts a white sky as ink. WHY IT LEFT EXTRACTION: it answered "does the timeline hold the pad the game held", which the capture layer's own copied pad answers exactly and for free, and it answered it at 82-94% on three clips the oracle certified exact -- every sampled disagreement its own digit confusion (L13 for L12, U83 for U82, a dropped letter). At extraction it was also reading almost nothing (65 of 477 cells on 7267) while costing ~3 s a clip. WHY IT STAYS: `tools/score_pad_read.py` and `tools/score_picture_offset.py` are the instruments that settle a picture-vs-pad question, `replay/oracleread.py` borrows its glyph machinery, and reading the pad off PIXELS is how CONSOLE input capture would work, where no RAM is readable. |
| The capture layer and installer | `plugin/gfxwrap/gfxwrap.c` wraps the user's Project64 graphics plugin, copies the address table at ProcessDList and publishes picture plus stamp through `replay/framestream.py`. `replay/pluginsource.py::table_for` takes addresses from the selected layout; decoding reuses `inputs/frame.py`. GLideN64_LINK_4.2 uses the wrapped ReadScreen path; direct GL capture is a separate path. `main.py` opens/writes the stream only inside the recorder-owned video factory, and releases it before recorder ownership transfers. `pictures_flow` verifies real picture production, with desktop fallback while the plugin is unavailable. `core/capturelayer.py` owns consented install/update/undo and refuses replacement while PJ64 is running. `tools/build_plugin.py` builds the tracked x86 DLL; a build is not an installation. `tests/test_composition.py` isolates live OS/plugin boundaries and tests owner/viewer behavior. Source identity, current interpretation and historical rejected offsets belong to [the chain](chain-input-timeline-frame.md). |
| The picture feed and retained media clock | `replay/media.py::MediaRun` owns encoder identity/origin. `ffmpeg_sink.py` assigns monotonic 90 kHz video PTS, trims pre-origin audio, preserves NUT -> TS timestamps and records the assigned PTS in `ledger.py`; segments retain their run. `extract.py` cuts with the same integer offset, disables timestamp shifting, uses 90 kHz MP4 edit lists, and returns `source_pts` plus browser `frame_times`. `feedmap.py` looks up exact source keys; no cadence/bias fit is allowed. `tests/test_replay_picture_identity.py` independently decodes painted picture IDs across encoders, fractional cuts, queued audio, stalls and timestamp collisions. The separate A/V flash/click check remains in `tests/test_replay_picture_feed.py`. |
| The PICTURE LEDGER (item 40 — capture's own per-picture record, the map's FIRST source) | `replay/ledger.py` — his spec 2026-08-28: "at every single frame of gameplay we have access to all the memory addresses and data in-game… embed each frame with extra information… extend the frame-by-frame information storage at any point". `recorder._on_frame` passes every grab to `PictureLedger.observe`, which dedups by EXACT equality of a stride-8 sample (pre-encode grabs of one presented picture are byte-identical; 93 µs/grab measured at 1600×1224, ~1.1% of a core at 120/s) and records one row per DISTINCT picture: composition time, RAM frame, plus every registered stamp (`ledger.stamps["name"] = callable` — ONE line extends the record). At extraction the clip's slice of those rows becomes the sidecar's `picture_ledger` — the durable per-frame record, stamps included — and `feed_map` joins it to the encoded frames. `observe()` never raises, so a ledger bug cannot cost capture. Torn grabs (a mid-update surface copy; 118 of 647 row gaps under 20 ms on attempt 4518) fold into their present row via `MIN_ROW_GAP_S`. **Debugging ANY timeline-vs-video report starts with `tools/inspect_timeline.py`** (item 44): `--frames` prints, per panel frame, the track pads, the map's slots and the ledger rows with their stamps; `--audit` walks the whole clip (row rate, torn pairs, stamp-vs-map residual stretches). The panel's FRAME readout is 0-based = the track axis |
| A+V single mux (ffmpeg subprocess) | `replay/ffmpeg_sink.py::FfmpegAvSink` — ONE ffmpeg muxes video (stdin) + audio (named pipe) on ONE wall-clock: `-use_wallclock_as_timestamps` before each input, `-fps_mode cfr` video, `-af aresample=async=1` audio → combined A+V MPEG-TS segments. THIS is the two-clock-drift fix (memory `replay-av-drift-two-clocks`); feeder pacing is not load-bearing. Segment→UTC = anchor-at-first-frame + CSV offset RELATIVE to the first segment. In-process fallback (no ffmpeg, legacy two-clock): `replay/encoder.py`. Encode QUALITY comes from `replay/config.py::video_quality_args`, not here |
| GC policy (stop-the-world watchdog + gen-2 idle collector) | `replay/_gcwatch.py` — freezes the startup heap, disables AUTO gen-2, runs manual `gc.collect(2)` during idle with a 5-min never-idle backstop; `arm(is_idle=recorder.is_idle)` from `server/app.py` lifespan |
| Audio (per-process tap primary, endpoint-by-pid fallback, RT-safe pump, deaf-stream watchdog) | `replay/audio.py` + `replay/_system_audio.py` — `ProcessAudioSource` (proctap / WASAPI **process** loopback) is PRIMARY so a clip carries the game and nothing else on the desktop; `SystemAudioSource` (device loopback of the endpoint hosting the pid's session) is the FALLBACK and records everything sharing that endpoint. Both factories take the **pid** (`recorder.py`), both feed the same `AudioPump` — a PURE RT-safe handoff (PCM → `recorder._on_pcm` → sink's audio pipe; no sample-count placement / silence injection, ffmpeg's wallclock+aresample own timing) — and both self-heal through the shared `DeafStreamWatchdog`. proctap yields float32; int16 is the one format on the wire to the sink. `proctap` must stay in `tools/build_exe.py::COLLECT` or the frozen exe silently degrades to desktop-wide capture. **`tools/probe_audio_isolation.py` is the live gate**: two ffplay children playing 440/880 Hz at once, only the 440 process captured — one tone proves the tap is alive, never that it is isolated (device loopback passes a one-tone test perfectly). Rejected alternatives and the deaf-tap escalation policy: docs/architecture.md audio facts |
| Clip extraction (ffmpeg cut of A+V segments) | `replay/extract.py` copies verified native H264/AAC with hidden decoder pre-roll and a 90 kHz MP4 edit list. Visible source PTS and decoded pixels remain exact; only negative discarded pre-roll packets are omitted from the output picture index. Unknown/reordered sources retain video re-encoding and audio copying. Both paths honor contiguous coverage and size/run boundaries and publish atomically with faststart. `tests/test_replay_picture_identity.py` checks lossless native pictures; `tests/test_ui_replay_copy.py` checks browser pre-roll handling. Timing scope and remaining tail wait: `docs/replay-review.md`. |
| Encode quality (ring sink + clip cut) | `replay/config.py` — `VIDEO_CQ`/`VIDEO_CRF` + `video_quality_args(codec, stage, maxrate)`, THE registry both encoders read. Constant-quality, never a bare bitrate (the "blurry recording" bug: extractor with no rate control fell back to ffmpeg's ~2 Mbps default, fixed 2026-07-23). Raising quality costs ring disk — `VIDEO_CQ` is the one knob |
| Clip save/extract/settings orchestration | `replay/service.py` — `ReplayService`: attempt→span→clip→save + user settings + `available_attempt_ids()`; `_coverage_notices` answers whether the clip is missing any of the ATTEMPT (`starts_mid_attempt` / `ends_early`, from the timestamps) as opposed to merely a short run-up -- `replay.js` drew its "Starts mid-attempt" warning off the coarse `truncated` flag until 2026-08-28, which put an alarm on an ordinary reset ("but... I just reset as normal? What does this even mean?"); `truncated` still ships and still means what it meant; same LookupError/ValueError/RuntimeError→HTTP taxonomy as api.py |
| Single-RECORDER guard (machine-wide) | `core/recorder_lock.py` — fixed temp-dir file lock so only ONE instance captures PJ64, even across exe + dev servers in separate worktrees (different data dirs → per-db instance_lock does NOT coordinate them; two recorders doubled GPU/encode/audio load, live 2026-06-15). `recorder.py` acquires in `_begin_capture` (can't → viewer-only, auto-takeover next attach cycle), releases in `_teardown_capture`. Injectable (`recorder_lock_factory`); tests redirect the path via conftest |
| Side-by-side compare (import jobs, CRUD, view, serve) | `compare/service.py` — composes `compare/importer.py` (yt-dlp/copy/upload-bytes → ffmpeg-normalize → content-addressed cache in `core/paths.compare_cache_dir()`, dedup = "load once"; atomic publish via `.tmp-<name>`+os.replace) + `storage/db.py` comparisons (migration v10). **Wired in main.py on ffmpeg alone, never gated on the db** (task 0053): a boot that loses the instance-lock race (the reload handoff — the old app's replay teardown can outlive the new boot's bounded wait) used to skip the router entirely, so every compare call 404'd and the tab read as "videos don't load" with nothing in any log; the service reads `tracker.db` per call, answers 503 until the reattach loop lands the db, then works with no restart (pinned by `tests/test_composition.py::test_dbless_boot_still_mounts_compare_and_compilation`, which covers compilation's identical gate). The UI half of the same incident: `compare.js` refetches the view on tab activation (a fetch that failed during a restart otherwise stuck all session — re-picking the same run is a state no-op) and every import/view failure now renders (`cmpError` / job error state), never a silent swallow |
| Failure compilation (build + job) | `replay/compilation.py` — `CompilationBuilder` reuses `ClipExtractor` per window then ONE concat-filter ffmpeg pass scales+pads to a common canvas (probed from the finale clip) and re-encodes to one MP4 (single clip → copy); `CompilationService` runs it as a polled daemon-thread job (mirrors `CompareService`), output → `compilations_dir()` |

## Recipe: add a user-visible replay setting

Bounds row in `SETTINGS_LIMITS` + plumb `validate_settings`/`save_settings`/
`apply_settings_file` (replay/config.py) → live-apply + getter in
`ReplayService.update_settings`/`settings()` → field on `SettingsBody`
(server/replay_api.py) → input in the recording-dot panel
(`ui/components/replay.js` BufferSettings) → README settings lines → tests in
test_replay_{config,service,api}.py. Mirror commits 69bb83d / 29fd542.
Settings persist in `data/replay_settings.json` (a JSON overlay beats a db
migration for scalars); corrupt/out-of-range files lose to defaults so the
server always starts.
