## The Scorecard card

Automatic goals (2026-09-06): an unset or cleared goal follows the current
scope's MARELO rank plus one subdivision. The owning derivation is
`ranks/scorecard.py::automatic_goal`, called with `ranks_api._score_scope`
from the card builder; no second average and no celebration-state writes.
The response identifies it as `kind: "automatic"`; the stored KV stays null.
Manual choices remain global across scopes. The picker labels automatic mode,
replaces it on a manual pick, and restores it when the last pick is removed
or Automatic goal is clicked. Capless IV–I now have finite selectable goals;
Capless V remains unbounded. Saving a named goal refetches the current scope.

## The goal's regions

**Round 24, and it started as a question about the import.** A 44"53 he could
see on the Ultimate Sheet never reached his card, and the import was right:
that time sits on the sheet's "[1] Big Bob-omb on the Summit (JP)" row, he is
graded on US, and `ratings.py::_visible_entries` drops a JP-tagged entry on a
row that HAS a US/JP distinction. Nothing was lost; one region was hidden.

So the Scorecard mounts the SAME `RegionSwitch` the Library does ("We should
reuse the JP/US selector in the library") with a different default: his
DETECTED region, not both. The pick lives in the ui_state KV
`scorecard_regions` beside `scorecard_goal`, for the same reason that one is
server-side — two clients, one choice. **Absent is not `["us"]`**: while the KV
has never been written the card follows `ranks.grading_version` live, so a mode
flip still moves it, and only a deliberate pick freezes it ("BUT it should be a
deliberate choice"). An empty list is a 422, never a silent fallback — "show me
nothing" and "follow my ROM" are different intentions and the control never
sends the first.

With both regions on, `runner_goal_map` reads `ratings.runner_times` ONCE PER
REGION (the memo is keyed by region, so the second read is free after the
first fetch) and keeps the FASTER per entity — "we simply take the faster time
across both regions" — which is the same minimise-then-merge shape
`resolve_multi` applies one level out, across goal SOURCES. `ratings.py`'s own
single-region contract is deliberately NOT widened: `_visible_entries` answers
"what does this row look like on THIS ROM", and a row's JP ladder is a
different ladder, not a longer list. Division and custom goals never read the
sheet, so this touches neither, and neither does the column export (a sheet
row carries its own region).
