## The runner page, its doors and the ▶ rows

- The scope chip row lives in `scopechips.js` (the account screen imports only it, never the Rank page). `runnerpage.js` draws through rankpage.js's exported `ScopeChips`/`CoverageStrip`/`Breakdown` pointed at `GET /api/leaderboard/runner/{name}` (+ `/summary`), **never a second implementation**; differences are props (`source`, `readOnly` — no ✎, no `EntityDetail` click, tiles `.is-static` — and `variant="runner"`).
- No cycle: rankpage.js never imports runnerpage.js; `app.js` picks the mount (`openRunnerName`, cleared on leaving Rank; `setTab(name, {keepRunner})`) and passes `onOpenRunner`.
- `LeaderboardCard` (between chips and MARELO card, `collapsible.js::Disclose`, closed per mount) OWNS the fetch (`useBoard`) so it opens onto loaded rows; tests and uilab stories open it through its real head (`OPEN_LEADERBOARD`). Your own row stays dead.
- Doors: `librarytarget.js::RunnerName` (one component for `ExampleCard` and `PlainEntry`, never on the synthetic You row); lit coverage tiles (`onOpen`, distinct from `onToggle`) and breakdown names (`.rank-entity-link`, art inside the button; own rows pass `you:true`) fire `openLibrary({kind:"target", entity, runner, timeCs})`. Navigating text wears `.textlink`. Entries carry `data-runner`/`data-time-cs`. An unrun tile stays `.is-static`.
- ▶ rows: runner rows play via `librarytarget.js::ExampleMedia`; own rows via `ReplayPlayer` when `pb_attempt_id` is in `/api/replay/available`; `BreakdownRow` builds one `playButton`; never a second embed path. The coverage strip has no scroll cap. Default segment exclusion is server-side (`.claude/rules/server.md`).
- Gate: `tests/test_ui_runner_page.py`.

## How full a rank bar is DRAWN (and the one bar that is never anchored)

`caps.js::barFill(tier, division, fill)` draws `0.5 + 0.5 × fill`, except the floor (`rankPosition(tier, division, 0) === 0`, never a `tier === "Iron"` literal). `rankclimb.js` converts ONCE at the plan boundary (`targetBar`/`startBar`), so every value in `climbplan.js` is a drawn width. The track's `title` gives the honest percentage from `graded.fill`. marelo.js's swap lerps two `barFill` widths. **Never anchor `LadderBar`** (the Rank tab ladder) or the Mastery meter. Guards: `tests/test_ui_rank_bar.py` (incl. inverse `test_the_rank_tab_ladder_is_never_anchored`), `tests/test_single_source.py`'s `FILL_ANCHOR`.

## Rank icon STYLE registry (hat + medal, room for more)

- Every call site renders `rankicon.js::RankIcon`; styles live in `ICON_STYLES` (`hat` first and default). A style owns only drawing; identity (name/colour/pattern) lives in `caps.js::CAP`, THE import-free tier registry. The preference is one module-level slot (`setRankIconStyle`, localStorage `sm64.rankIcons`); store.js only proxies it. Guards: `test_no_call_site_imports_a_style_renderer_directly`, `test_hat_is_first_and_every_icon_style_has_a_renderer`; judge a new style on `tools/hat_sheet.py`.
- `capName()`/`divisionDigit()` are the ONLY display conversions; storage stays Roman/keyed (`tests/test_ui_cap_names.py`). `Hat` defaults its `title`; aggregate surfaces render `tier ? <Hat/> : "–"`. Medal ink derives from luminance, never a per-tier table.
- **Numeral + wings are a data rule alone (`division != null`), no size floor**; `DETAIL_MIN_SIZE` tunes only ring opacity and `glyphFraction`. `wingTiers` gates wing count on division; Capless never has wings, handled only inside `wingTiers`. Capless's ring is dotted by a second %-sized mask; its under-fill stays solid.
- `Hat`'s outer box is the cap footprint on both axes; wings spill — never `overflow: hidden` on `.hat`. `.fill` and `.shade` share one `--art`, built only by `hat.js::tintedPair`; `.hat .glyph` needs two classes, `inset: auto` before `left`/`top`.
- Tier colours: every pair distinct (redmean ≥ 185, pattern-aware `combined_distance`). Large surfaces use `capGradient(tier) || rankColor(tier)`; small marks stay flat. `flap` is celebrate.js-only (reduced-motion gated); `foldWings` is `TierRankUp`'s boundary tick only (`.claude/rules/ui-climb.md`).

## Rank tab (scope chips / picker / card / coverage strip / chart / breakdown)

- One view for Overall / route / course scopes; the picker defaults to `/api/marelo/scopes`' `active`. `t.mareloRev` is a fetch dependency; a scope switch clears the old data up front.
- `Breakdown` opens in served order (route order on a route); icons only through `EntityArt`; Score/Gain in points; "Next rank" is server-computed, target-only (`"→ Platinum IV"`, `"Maxed"`, "not practiced yet"), never re-derived in JS.
- `HistoryChart`: gridlines mirror `SCORE_ANCHORS` as a constant table; X zooms anchored at the newest point, clipped not filtered; Y eases from the whole ladder; rank-up dots via `rankUpKind` only when the rating rose; wheel uses functional `setZoom` (`tests/test_ui_rank_chart.py`).
- Mastery stays 0-100 on a plain `.rank-progress-track`, never a ladder, never converted to points; the Gold quest target lives in the Gain tooltip. `ScopeChips` reads `/api/marelo/summary` (side-effect-free `_score_scope`, never `_build_marelo`) and calls the same `setScopeId` as the select.
- `LadderBar` plots MARELO's tier/division/score, never Mastery: nine `.rank-band`s, `flex-grow: band.to - band.from`; no permanent division-icon strip. Reached = `.rank-band-fill::after` tier-independent gloss; `.rank-band-base` stays `.26` unfiltered; keep the gloss's average alpha under ~.22 or it washes hues out. `tests/test_ui_rank_ladder.py` is two-sided (lit/unreached ≥ 2.4, unreached-vs-plate redmean ≥ 40).
- Only your own rank shows permanently (icon + YOU), as a child of the band matching `tier`, at its clamped local fraction; your division's showcase icon is suppressed in your band only; pips never. Pips (`index/5`) and icons (`(index+0.5)/5`) are siblings computed from one `index`. **`.rank-band` has exactly ONE `transition`; the hover rule never declares its own.** The marker stays at its true fraction, never snapped to the vacated slot. Expansion is `max(260px, calc(var(--band-weight) * 1%))`, siblings `min-width: 0`. `:hover, :focus-within` share a rule, `:focus-visible` shows an outline; reduced motion gates only transitions.
- `CoverageStrip`: every non-excluded entity as an `EntityTile` (count == `n`), icon via `entityIconSrc(t, entity.key)`, ✎ via `useIconPicking` (stops propagation); tiles are buttons opening `EntityDetail` from `t.view`, no new endpoint; `.entity-tile` is `flex: 0 0 auto`; rows are `.rank-factor` DIVs, never `<label>`s.
